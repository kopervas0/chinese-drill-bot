# Как добавлять и менять колоды и задания

Колода — это один файл `.json` в этой папке. Бот и мини-приложение читают одни и те же файлы, отдельно ничего настраивать не нужно. В одной колоде могут быть карточки со словами и свои задания: тесты, пары, пропуски.

Колоды правятся как обычные файлы в репозитории. Ниже описан формат файлов.

## Формат файла

Файл `hsk4.json` (в колоде должен быть хотя бы один из разделов `cards`, `tests`, `pairs`, `cloze`):

```json
{
  "name": "HSK 4 — первые слова",
  "cards": [
    { "hanzi": "经验", "pinyin": "jīngyàn", "translation": "опыт" },
    { "hanzi": "打电话", "pinyin": "dǎ diànhuà", "translation": "звонить по телефону" }
  ],
  "tests": [
    {
      "question": "Как по-китайски «спасибо»?",
      "options": ["谢谢", "再见", "对不起"],
      "answer": 0,
      "explain": "谢谢 (xièxie) — спасибо."
    }
  ],
  "pairs": [
    { "left": "一", "right": "один" },
    { "left": "二", "right": "два" }
  ],
  "cloze": [
    {
      "text": "我 ___ 水。",
      "options": ["喝", "吃", "看"],
      "answer": 0,
      "translation": "Я пью воду."
    }
  ]
}
```

- **Имя файла** — латиница, цифры, `-` и `_`, до 30 символов (`hsk4.json`, `food-basic.json`). Это внутренний код колоды: после того как ученики получили коды прогресса, файл переименовывать нельзя.
- **name** — название, которое видят ученики.

### Карточки (`cards`)

Дают режимы «Карточки», «Квиз», «Обратный квиз», «Тоны», «Найди пары» и «На слух».

- **hanzi** — иероглифы.
- **pinyin** — со знаками тонов (`nǐ`, `shuǐ`), не цифрами (`ni3`). Слоги одного слова пишутся слитно (`diànyǐng`), слова во фразе через пробел (`dǎ diànhuà`). Безударные слоги без знака (`ma`, `de`) допустимы, но такая карточка не попадёт в режим «Тоны».
- **translation** — перевод, несколько значений через `;` (`быть; являться`). В квизах это текст кнопки, поэтому лучше коротко.
- **audio** — необязательное поле, обычно не нужно: в мини-приложении озвучка встроена, а режим бота «На слух» включается только у колод с голосовыми.

### Тесты (`tests`)

Вопрос и варианты ответа, режим «Тесты».

- **question** — текст вопроса.
- **options** — от 2 до 6 вариантов, все разные. Порядок при показе перемешивается.
- **answer** — номер верного варианта, **считая с нуля**: первый вариант — `0`, второй — `1`, и так далее.
- **explain** — необязательное пояснение, его видят после ответа.
- **audio** — необязательное аудио к вопросу (задание «на слух»): `audio/имя.mp3` (файл лежит в папке `webapp/audio` сайта приложения) или `file_id` голосового из Telegram. Путь работает и в боте, и в приложении, `file_id` — только в боте.

### Пары (`pairs`)

Что с чем соединить, режим «Свои пары» (нужно минимум 2 пары). `left` и `right` — любой текст: иероглиф и перевод, слово и антоним, вопрос и ответ.

### Пропуски (`cloze`)

Предложение с пропуском, режим «Заполни пропуск».

- **text** — предложение, на месте пропуска три подчёркивания `___` (ровно одно место).
- **options** и **answer** — как в тестах.
- **translation** — необязательный перевод всего предложения, его видят после ответа.

Своими заданиями ничего не «выучивается»: по ним считается только результат занятия, код прогресса не выдаётся.

В JSON нельзя ставить запятую после последнего элемента списка и нельзя писать комментарии.

## Добавить новую колоду

1. Создайте файл `data/decks/имя.json` по образцу выше.
2. Проверьте (см. ниже) и опубликуйте (см. ниже).

## Изменить существующую колоду

- **Исправить перевод, пиньинь, вопрос или варианты** — безопасно, прогресс учеников сохранится.
- **Добавить, удалить, переставить карточки (`cards`) или поменять иероглиф** — старые коды прогресса этой колоды перестанут подходить, ученик начнёт колоду заново. Поэтому новые слова лучше выносить в новую колоду (`hsk4.json`), а не дописывать в старую. Задания (`tests`, `pairs`, `cloze`) можно добавлять и менять свободно, на коды они не влияют.
- **Удалить колоду** — удалите файл. Коды этой колоды перестанут работать.

## Проверка перед публикацией

На компьютере, в папке проекта:

```bash
npm run decks:check
```

Команда проверит все колоды: читается ли файл, заполнены ли поля, верно ли указан номер ответа, есть ли `___` в пропусках, нет ли цифр вместо тонов, нет ли повторов. Строки «ОШИБКА» нужно исправить, «внимание» стоит прочитать, «заметка» — справочная. Неверные задания бот и приложение просто пропускают (в логе сервера останется пометка), поэтому не пропускайте ошибки при проверке.

## Публикация

Мини-приложение обновляется само после каждого изменения колод в ветке `master` на GitHub. Бот берёт свежие колоды с сайта при каждом запуске (после простоя он «просыпается» и обновляется сам).

**Способ 1: прямо на сайте GitHub, без установки программ.** Откройте репозиторий → папка `data/decks` → нужный файл → значок карандаша → внесите правки → **Commit changes**. Здесь автоматической проверки нет, поэтому лучше сначала проверить текст на компьютере. Если файл не читается как JSON, бот не запустится, а сборка сайта завершится ошибкой (на сайте останется прежняя версия). Для доступа к приватному репозиторию человеку нужно быть его участником.

**Способ 2: на компьютере.**

```bash
npm run decks:check
git add data/decks/имя.json
git commit -m "Колода: имя"
git push origin master
```

Через 3–5 минут новые колоды появятся в мини-приложении (из-за кеша иногда нужно закрыть и снова открыть его), а в боте — при его следующем запуске.

## Как убедиться, что всё вышло

- Бот: команда `/train` покажет новую колоду в списке, а в её меню будут нужные форматы.
- Мини-приложение: новая колода появится на главном экране.
